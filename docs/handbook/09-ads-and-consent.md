# 09 · Реклама, свои рекомендации и согласие на маркетинг

Утверждено 17.08.2026. Это спецификация, а не предложение: следующий, кто
трогает рекламные слоты или галочку согласия, работает по этому файлу.

Все размеры в CSS-пикселях, все деньги в целых центах, вся вёрстка на токенах
из `apps/web/src/app/globals.css` — своих цветов и радиусов рекламные
компоненты не вводят.

---

## 1. Три формата, четыре файла

Рекламодателю нужна **одна** картинка, чтобы попасть во все слоты. Больше
форматов не принимаем — иначе спецификацию невозможно продавать.

| Файл | Размер | Пропорция | Формат | Вес |
|---|---|---|---|---|
| Основной | 1200 × 900 | 4:3 | JPG · PNG · WebP | ≤ 400 KB |
| Широкий *(необязателен)* | 1920 × 600 | 16:5 | JPG · PNG · WebP | ≤ 500 KB |
| Видео | 1280 × 720 | 16:9 | MP4 H.264 · WebM | ≤ 8 MB |
| Постер к видео | 1280 × 720 | 16:9 | JPG | ≤ 300 KB |

- Широкого нет → генерируем из основного: центр остаётся, поля размываем.
- Видео **всегда без звука**, ≤ 15 с, автоплей в цикле, без кнопки звука.
- `prefers-reduced-motion: reduce` → вместо `<video>` показываем постер.
- Безопасная зона: логотип, текст и лица — в центральных 80 %. Края в разных
  слотах обрезаются по-разному.

Три типа кампании: **статика** (1 картинка), **карусель** (2–5 картинок),
**видео**. Ничего больше.

### Длина текста

| Поле | Лимит |
|---|---|
| Рекламодатель | 24 |
| Заголовок | 48 |
| Описание | 90 |
| Текст кнопки | 20 |

Длиннее не обрезаем многоточием — не принимаем на загрузке.

## 2. Семь слотов

| Слот | Пропорция | Статика | Карусель | Видео | Плотность по умолчанию |
|---|---|:-:|:-:|:-:|---|
| Лента каталога | 4:3 | ✓ | ✓ | ✓ | каждая 6-я карточка |
| Шапка категории | 16:5 | ✓ | — | ✓ | 1 на страницу |
| Страница лота · боковая колонка *(только desktop)* | 16:9 | ✓ | ✓ | — | 1 |
| Страница лота · «Līdzīgi loti» | 4:3 | ✓ | — | — | 2 |
| Трансляция · пауза между лотами | 4:3 | ✓ | ✓ | ✓ | каждый 3-й лот |
| После оплаты / после проигранного лота | 4:3 | ✓ | — | — | 1 |
| Шаг оплаты | 4:3 | ✓ | — | — | 1 |

Плотность, разрешённые форматы, разрешён ли свой контент и рубильник
«выключить слот» — всё в админке, страница **Izvietojumi**. В коде хардкода
плотности нет.

### Порядок заполнения слота

```
платная реклама → продвинутый лот → своя рекомендация → слот схлопывается
```

Пустых рамок не бывает: либо контент, либо элемента нет в DOM.

## 3. Три источника контента, три метки

| Источник | Метка | Класс метки |
|---|---|---|
| Платная реклама | `Reklāma` | `.ad-mark` |
| Своя рекомендация (подборка, категория, трансляция) | `Ieteikums` | `.ad-mark.is-own` |
| Продвинутый лот продавца | `Apmaksāts izvietojums` | `.tag.tag-promo` |

Метка видна всегда и **не отключается ни в одном из трёх случаев** — ни
настройкой в админке, ни полем в кампании. Вешать юридический термин
«Reklāma» на собственную подборку нельзя: это неверно по смыслу и роняет
доверие, поэтому у своего контента отдельная метка.

Продвинутый лот — это настоящий лот с настоящей ставкой. Карточка обычная,
отличается только меткой. Карточку, которая выглядит как лот, но лотом не
является, не принимаем.

---

## 4. Два правила, которые нельзя нарушать

1. **Метка всегда видна.**
2. **Ни один слот не стоит вплотную к кнопке, нажатие на которую стоит денег.**
   Реклама на шаге оплаты идёт **под** кнопкой «Apmaksāt», не над. Промах
   пальцем в рекламу вместо оплаты — это потерянный заказ, а не потерянный
   показ. В трансляции реклама живёт только в паузе, когда кнопки ставки нет
   в DOM.

Чего не делаем никогда: всплывающих окон на входе, полноэкранных
интерстишлов, липких баннеров (снизу уже док), рекламы внутри модалки ставки,
автоматического звука.

## 5. Компоненты и классы

Всё в `apps/web/src/app/globals.css`, отдельного файла нет.

| Класс | Что это |
|---|---|
| `.ad` | карточка: геометрия лота, `.ad-art` 4:3, `.ad-body` |
| `.ad.is-side` | та же карточка в боковой колонке, `.ad-art` → 16:9 |
| `.ad-mark` / `.ad-mark.is-own` | метка «Reklāma» / «Ieteikums» |
| `.ad-track`, `.ad-slide`, `.ad-dots`, `.ad-dot` | карусель |
| `.ad-video`, `.ad-play`, `.poster` | видео и постер |
| `.adrow` | строка: картинка 84 px 4:3 слева, текст справа, `.mark` справа сверху |
| `.adwide` | широкий баннер 16:5, на ≤ 640 px → 3:2 |
| `.adbreak` | обёртка паузы в трансляции |
| `.tag-promo`, `.lot.is-promo` | продвинутый лот |
| `.slot`, `.fmtpill`, `.pick`, `.spec` | админка: слоты, форматы, выбор мест, таблица размеров |

Показы считаются на сервере по атрибуту `data-ad` (реклама) и `data-promo`
(своя рекомендация) — атрибуты не переименовывать.

## 6. Согласие на маркетинг

**Правовая рамка:** GDPR ст. 7. Согласие свободное, конкретное,
информированное, однозначное, и «чётко отличимое, в понятной и легкодоступной
форме» (ст. 7(2)). LV, EE, LT — все три рынка под этим.

### Что зафиксировано

- Галочка **не проставлена заранее**. Никогда.
- Строка одна, 13 px, обычный вес, `--text-2`. Класс `.optin`. **Мельче или
  бледнее делать нельзя** — согласие, полученное незаметной галочкой,
  ничтожно, и вся собранная им база подлежит удалению целиком.
- Галочка стоит **прямо над CTA** — это законно, порядок элементов не обман.
- Ничего не блокирует: без галочки регистрация, ставка и оплата проходят.
- Каждое согласие пишется в журнал: дата, редакция текста (`v2`, `v3`), IP,
  источник. Записи не удаляются, только отзываются. Админка → **Piekrišanas**.
- Отписаться можно всегда: кабинет → «Paziņojumi», тумблер.
- Предупреждения о перебитой ставке — транзакционные, выключить нельзя,
  тумблер заблокирован.

### Пять точек, где спрашиваем

| Точка | Текст | Ожидаемое согласие |
|---|---|---|
| Регистрация | `Gribu pirmais uzzināt par jauniem lotiem manās kategorijās.` | низкое |
| Модалка ставки | `Brīdini mani par līdzīgiem lotiem.` + `Neietekmē solījumu.` | среднее |
| Проигранный лот | `Paziņo man, kad parādās nākamais {категория}.` | **высокое** |
| Победа | `Brīdini mani, kad parādās līdzīgi {категория}.` | **высокое** |
| После оплаты | `Sūtiet man arī jaunumus par gaidāmajām izsolēm.` | среднее |

Текст всегда от выгоды покупателя и по возможности с категорией лота —
это и есть рычаг конверсии, а не размер шрифта.

### После согласия

`marketingConsent` приходит из `GET /api/public/auth/me`. Если `true` —
`.optin` не рендерится ни в одной из пяти точек. В кабинете тумблер остаётся,
иначе отписаться будет негде.

## 7. Как согласие попадает в базу и в админку

### 7.1 Таблица журнала — только на добавление

Новая миграция `packages/db/migrations/00xx_consents.sql`:

```sql
CREATE TABLE consents (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  customer_id    uuid REFERENCES customers(id),
  -- анонимный посетитель: id из куки, до того как он зарегистрировался
  visitor_id     text,
  kind           text NOT NULL,   -- marketing | cookies_analytics | cookies_ads
  granted        boolean NOT NULL,-- true = дал, false = отказал или отозвал
  text_version   text NOT NULL,   -- 'mkt-v3'
  text_snapshot  text NOT NULL,   -- сам текст, как его видел человек
  lang           text NOT NULL,   -- lv | ru | en | et | lt
  source         text NOT NULL,   -- register | bid_modal | lot_lost | lot_won
                                  -- | checkout_paid | account | cookie_banner | admin
  market_code    text REFERENCES markets(code),
  ip             inet,
  user_agent     text,
  created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX consents_customer_idx ON consents (customer_id, kind, created_at DESC);
CREATE INDEX consents_created_idx  ON consents (created_at DESC);
```

Плюс два денормализованных поля на `customers` — это кэш для быстрой
отрисовки, **не источник истины**:

```sql
ALTER TABLE customers
  ADD COLUMN marketing_consent    boolean NOT NULL DEFAULT false,
  ADD COLUMN marketing_consent_at timestamptz;
```

Правила:

- Согласие = `INSERT` в `consents` + `UPDATE customers`. Всегда вместе, в одной
  транзакции.
- Отзыв = **новый** `INSERT` с `granted = false`. Строки не обновляются и не
  удаляются никогда — `UPDATE` и `DELETE` по этой таблице в коде запрещены.
- Истина = последняя строка по `created_at` для пары (`customer_id`, `kind`).
- Анонимный посетитель пишется по `visitor_id`; при регистрации его строки
  привязываются к `customer_id`.
- `text_snapshot` пишем целиком. Через год, когда текст поменяется трижды,
  доказать согласие можно только тем текстом, который человек видел.
- Меняешь формулировку → поднимаешь версию (`mkt-v3` → `mkt-v4`). Существующую
  версию править нельзя.

### 7.2 Запись на фронте

```
POST /api/public/consent  { kind, granted, source }
```

- Авторизован → `customer_id` из сессии.
- Не авторизован (галочка стоит в форме регистрации) → согласие уходит вместе с
  `POST /auth/register` одним запросом, чтобы не было состояния «зарегистрирован,
  но согласие потерялось».
- `ip` и `user_agent` берёт сервер из запроса, фронт их не присылает.

### 7.3 Где это видно в админке

**Три места, по возрастанию детальности:**

1. **Карточка клиента** → блок «Piekrišanas». Текущее состояние (`Piekrita` /
   `Nav` / `Atsauca`), дата, источник, версия текста, и вся история строк ниже.
   Это первое, куда смотрит оператор, когда клиент звонит и говорит «я не
   подписывался».
2. **Страница «Piekrišanas»** (экран 17) — общий журнал по всем клиентам.
   Фильтры: тип, период, только согласия / только отзывы. Кнопка «Eksportēt CSV».
3. **Список клиентов** — фильтр `Mārketings: jā / nē` и счётчик. По нему
   собирается список рассылки.

`GET /api/admin/consents?kind=&from=&to=&customerId=&granted=&page=`

**IP в интерфейсе замаскирован** (`85.254.—.—`). Полный адрес виден только роли
с правом `consents.view_ip` и в CSV-экспорте — это персональные данные, и
показывать их каждому оператору незачем.

### 7.4 Кто имеет право получить письмо

Рассылка собирается по `customers.marketing_consent = true`, но перед отправкой
воркер **перепроверяет последнюю строку журнала**. Если кэш и журнал расходятся,
письмо не уходит, а расхождение попадает в `worker_status`. Кэш может отстать —
журнал нет.

Транзакционные письма (перебита ставка, выиграл, оплата, доставка) идут
независимо от согласия. Это не рассылка.

### 7.5 GDPR-удаление

При стирании клиента (`customers.erased_at`) персональные данные из `customers`
уходят, а строки `consents` остаются с тем же `customer_id`. Журнал — это
доказательство того, что рассылка была законной, и он должен пережить стирание
профиля.
