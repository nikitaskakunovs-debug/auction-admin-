# 16 · Страница лота: полная опись элементов

Второй файл-опись, парный к главе 15. Причина та же: при перерисовке страницу
легко упростить до «фото, цена, кнопка», а в ней **34 элемента**, и половина
видна только в определённом состоянии.

**Правило: любой новый эскиз страницы лота проверяется по этому списку до
показа.** Источник истины — `apps/web/src/components/LotPage.tsx` (706 строк).

Экраны: `x01`–`x06`.

### Найденный дефект: счётчик кадров невидим

`globals.css:924` — `.lcount{left:16px;bottom:16px}`
`globals.css:1378` — `.lfull{left:12px;bottom:12px}`

Обе в левом нижнем углу, `.lfull` объявлена позже и рисуется поверх. Кнопка
«Pilnekrāna» **полностью закрывает** «2 / 5». Счётчик уводим наверх:
`.lcount{top:16px;bottom:auto}` — слева вверху свободно, `.lnav.p` центрирована
по вертикали.

**Три способа назвать сумму** — быстрые кнопки, ±, ручной ввод — не избыточность.

**Прокси-ставка (`.maxrow`)** — механика аукциона, а не настройка. Без неё
человек обязан сидеть у экрана до конца.

## F. Поля, которых в движке ещё нет

`LotPage.tsx:26-40` — тип `LotReport`. Блоки появятся сами, когда API начнёт их
отдавать:

`inspectedOn`, `tested`, `packaging`, `included`, `missing`, `flaws`, `specs`,
`authenticity`, `terms`, `seller`, `watching`, `gradeCode`, `retailCents`,
`buyNowCents`.

**В эскизах рисуем их всегда.** Иначе при подключении окажется, что места для
них в вёрстке нет.
