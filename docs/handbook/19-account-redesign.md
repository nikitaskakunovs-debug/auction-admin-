# 19 · Кабинет: перенос утверждённого макета в код

Источник — ваш пакет `izsolidizainpaket.zip`. Ничего не перерисовывал:
CSS взят из `new.css` пакета как есть, разметка собрана под те же классы,
экраны сверены со скриншотами пакета.

## A. Что НЕ трогали

| | Почему |
|---|---|
| Верхняя строка сайта, логотип, поиск | Договорились. Раздел «ШАПКА: sticky» из `new.css` пакета намеренно **не** переносился |
| Меню и нижний док | То же. Док уже починен раньше: не мигает, все подписи видны |
| Главная, каталог, фильтры, карточка и страница лота | Отдельные заходы |
| Движок, суммы, комиссия, PVN | Значения приходят с сервера и верны |

## D. Что нужно от бэкенда

Экран уже вызывает эти адреса; пока их нет — поля пустые, а ошибку сохранения
экран показывает честно и возвращает переключатель обратно.

1. **`PATCH /api/public/me`** с телом `{ alias?, marketingOptIn? }` — такого
   адреса нет вовсе.
2. **`GET /api/public/auth/me`** должен отдавать `emailVerified` и
   `marketingOptIn`. Сейчас возвращает `id, email, alias, country, blocked,
   strikes`.
3. В таблице `customers` нет ни признака подтверждения e-mail, ни согласия.
   По главе 09 согласие должно жить в отдельной таблице `consents` со снимком
   текста и версией — её тоже ещё нет.
4. Даты «Solītājs kopš 05.2026» и «Parole mainīta 11.05.2026» из макета
   требуют `createdAt` и `passwordChangedAt` в ответе `auth/me`.
